# 大规模本地图库的性能边界

2026-10-04 的实施基线。目标规模为 1000 套／10 万媒体，压力档为 5000 套／30 万媒体；性能数字必须注明硬件、构建模式、缓存状态和是否使用真实文件。

审计确认的主要瓶颈是整库 JSON 持久化、启动和普通修改时的整库解析／克隆／重写，以及按文件反复持久化授权表。Edge 的真实 localStorage 在十万级合成元数据写入时触发容量错误；内存模拟存储通过测试不能排除这一问题。本阶段将桌面存储、查询、写入和授权改为有界接口，同时保留浏览器演示适配。

## 存储与查询

- 桌面元数据保存在应用数据目录的 `catalog.sqlite3`，媒体二进制留在原位置。浏览器演示仍使用 MockRepository，不作为十万级持久化方案。
- 资料记录使用 JSON 字段保存可扩展属性；写真内容顺序、模特关联、档案照片、标签和标签分组使用独立关系表及外键。保存资料和关联、导入及删除标签在事务内完成。
- `user_version` 标识 schema，较新的版本拒绝打开而不改写。首次迁移保留原始 `legacy-v1.json`，成功标记与资料同事务提交；原 localStorage 不删除。独立旧浏览记录以最多 40 项迁移。
- SQLite 使用 WAL、FULL 同步及 5 秒忙等待；单连接页缓存预算 64MiB。后台任务处理查询和事务，UI 不执行 SQL。
- `catalog_view` 返回当前页面窗口，列表最多 96 项，候选选择器最多 48 项。首页只取有限写真摘要；查看器只返回当前媒体、位置和相邻 ID。查询以 SQL 排序和分页结果为准。
- `useData().db` 在桌面端是局部快照，不能据 `db.media.length`、`db.albums.length` 推断全库数量，也不能用它替换完整图库。总量来自 `page`，写真 `_summary` 来自持久化摘要，完整编辑关联通过明确读取接口取得。
- 写真详情展示实体的 `mediaIds` 为空，显示使用 `page.visibleMediaIds`，全套浏览起点使用 `page.firstMediaId`；模特详情不附全部 `photoIds` 或未展示的档案媒体。`catalog_entity` 为编辑器明确读取完整关系；读取完成前不建立可保存草稿，失败保留重试入口。字段 patch 不得据展示空数组删除完整关系。
- 同页筛选、排序和候选来源切换保留已挂载的容器与旧结果，最新查询成功后替换；旧响应不得覆盖新查询。等待期间的旧快照只供显示，不用于写入或接续分页。卡片使用稳定实体 ID，跨行重排与 48 项虚拟化阈值不重建仍可见的卡片；收藏媒体查看器同样保留来源页面，退出不重复读取来源。
- 普通字段修改通过 `catalog_patch` 提交差异；关系操作通过 `catalog_operation` 提交可序列化输入。旧 `Repository.update(callback)` 只保留给浏览器演示，不跨 IPC。
- 中文子串搜索针对最多 5000 套写真摘要，摘要包含模特名和媒体标签；暂未引入中文分词。改动媒体标签只更新引用它的写真摘要。单套查询、筛选和分页不解析全库 JSON。
- 写真库、模特详情的关联写真、写真集媒体与收藏连续向下浏览，靠近末尾时自动接续最多 96 项的查询窗口，不展示分页、查看更多或跳页控件。已读元数据保留至离开当前页面，DOM 与图片解码由虚拟网格限制在视口附近。大图查看覆盖在已有写真集页面之上，独立读取当前媒体与相邻 ID；简单退出不重查或重建底层页面，保留滚动、筛选和布局状态。编辑草稿保留完整关系并可跨候选窗口修改；关联写真集与关联模特选择器在各自滚动区域接续最多 48 项的候选窗口，保留已加载的选择项与失败重试，取消不提交。
- 写真详情三种媒体布局共享几何虚拟化；超过 48 项时只挂载视口及相邻缓冲范围，保留键盘焦点与相邻项。布局改变时按稳定媒体 ID 保留阅读位置。宽高未知时从已加载缩略图获取显示比例，只保存在该页内存，不为排版读取原图或批量改写媒体元数据。
- 媒体布局在几何变化时建立区间索引，滚动查询跳过屏外子树，不逐帧遍历全部媒体；索引与该页面布局同生命周期，使用两组有界长度的数值数组。卡片焦点和比例回填用稳定 ID 索引；网格滚动只刷新文档偏移，列数与宽度由尺寸变化通知测量。
- 页面及全局资料编辑器按需加载；Suspense 位于路由内容和编辑器内，保留导航及查看器下方的来源页面。`npm run check:performance` 在构建后检查完整静态依赖闭包：入口原始 JS 不超过 670000 字节，包含发现页的首屏不超过 720000 字节；不以单个入口文件大小代替首屏总量。该检查已接入 CI。
- 本地 `npm run verify` 与 CI 共用构建、预算和单元检查；正式更新也执行首屏和桌面体积检查。安装记录与原生验收共用 `scripts/build-fingerprint.ps1` 定义构建输入，`check:installed` 拒绝源码指纹或 exe 哈希不匹配，具体用例另核对运行前端入口。

## 文件与资源预算

- Release 保留默认速度优化，开启跨 crate LTO、单代码生成单元与符号剥离。构建后执行 `npm run check:size`；Windows 原生构建后执行 `npm run check:size -- --desktop`。前端发布目录预算 1.5 MiB，exe 预算 16 MiB，CI 与本地正式更新均检查相应产物。测试素材、开发依赖和编译中间文件不属于桌面发布体积。
- 本地更新成功保存安装记录后，仅保留两份生成的 exe 回滚备份，必须包含刚替换的程序；清理不递归、不匹配用户命名文件，不处理图库、原件或 WebView2 用户配置。该规则限制安装目录持续增长，运行缓存按下列独立预算维护。

- 原生选择器可从模特/写真总目录逐层发现写真，每套媒体只扫描当前层，不追随符号链接或 Windows 重解析点。批量核对列表按可见范围挂载，草稿不写入正式图库；逐套确认事务使用最新导入上下文，按实际路径复用媒体，成功项不重复提交。扫描上限及错误呈现见交互规范。重选目录可恢复已登记文件的精确权限。
- 原图使用稳定媒体 ID 的 `jingji` 协议；后端按登记路径及权限查询，并核对规范路径。视频支持有界字节范围响应，图片响应限制 64MiB。缓存协议授权只开放专用缓存目录。
- 旧 Tauri 文件授权表只在首次迁移加载；之后启动不恢复十万条 glob 授权。新导入不逐文件触发整表授权持久化。
- 普通列表只读缩略图，失败显示占位及独立重试入口；缩略图失败不回退原图。发现页图片按显示尺寸、设备像素比和原图比例请求 1024/2048/3072px 高清缓存（JPEG 92），不统一加载最大档，也不直接解码完整原图。仅可见与近视口图片订阅生成任务，封面优先于叠放叶片；高档加载期间保留当前低档图。正式头像按显示尺寸、设备像素比、原图比例及裁切倍率请求高清缓存；选择阶段和其他普通列表可使用 512px 预览。预览视频与正式查看分离，离开时停止并释放资源。
- 首页查询继续验证封面稳定媒体 ID 的权限、规范路径、文件大小和修改时间。高清缓存请求也重新核对授权和文件元数据；源文件改变生成新缓存指纹，撤销授权不显示跨页面旧图。沉浸查看仍加载原图。
- 图片原生响应使用 `private, no-cache` 和基于文件元数据的弱 ETag；每次条件请求先核对文件权限与路径，未变化时返回 304，避免重复传输原图。视频及字节范围响应继续使用现有有界读取和 `no-store` 策略。首页返回不重复播放页面和推荐卡片的入场动画；标题悬停效果保留。
- 图片缓存支持 512/1024/2048/3072px 长边，不放大尺寸不足的原件；按来源与尺寸联合去重。前后端生成并发均为 2，前端队列最多 256 个来源/尺寸任务。离开视口取消无订阅的等待任务；已经运行的原生解码最多剩两个任务。
- `image_thumbnail` 返回 `http://jingji.localhost/thumbnail/<缓存指纹>`。资源接口只接受 64 位小写十六进制指纹，读取专用缓存目录内的普通 JPG 文件；不接受磁盘路径，不依赖旧 asset scope。
- 缓存指纹包含规范路径、文件大小、修改时间和生成版本；检查请求时重新验证。专用缓存预算 512MiB／10 万文件。首个成功请求调度后台清理，后续累计至少 32 次生成且距上次尝试至少 60 秒时调度；同时只运行一次扫描，清理不占用缩略图响应的同步路径，失败不使已生成图片加载失败，稍后可重试。扫描期间的新生成计数保留。最近 60 秒使用或生成的文件受到保护，删除前重新检查时间；派生目录预算为软上限，保护期和两次清理间隔内允许临时超额。原件及临时生成文件不参与淘汰。
- 解码检查尺寸及预计输出，`image::Limits.max_alloc` 是尽力限制，不能据此声称进程内存有严格上限。查看器只挂载当前原图，本阶段不预加载额外原图。

## 验证与仍需实测的边界

视频兼容播放使用已安装的 FFmpeg/ffprobe。后端先验证稳定媒体 ID、视频类型、文件权限及规范路径，再探测编码；MP4/M4V/MOV 的常见 H.264 8 位 4:2:0 + AAC/MP3 直接播放，其余情况生成独立 H.264/AAC MP4 副本。副本保留分辨率（奇数尺寸只对齐到偶数）、帧率与时长；多音轨取首条，暂不呈现字幕或 HDR 色调映射。前端公开准备进度，不改原件、不写入媒体记录，也不把悬停当作正式浏览。

视频封面复用受限缩略图队列，`image_thumbnail` 的 `video:<编码后的媒体ID>:<10|50|90>` 来源仅解析已授权的视频，按原件版本与取帧位置生成最长边 512 的 JPEG。默认 10% 对不超过 10 秒的视频取起始帧；显式 50% / 90% 仍按时长选取。封面与图片共用 512 MiB 的缩略图预算。

悬停优先直放或复用完整播放缓存；其余视频仅准备开头最多 12 秒、最长边 640、无音轨的 H.264 预览副本。预览沿用同一生成互斥、取消与租约机制，处理超时 45 秒、输出限制 32 MiB，纳入播放缓存总预算；以 `preview-<原件指纹>` 区分预览缓存与完整播放副本。预览进度按短片时长计算，卡片时长按原件可得信息显示。

`prepare_video` / `cancel_video` 通过请求 ID 管理取消，生成并发为 1，FFmpeg 解码及编码线程均限制为 2。切换、返回和正常退出取消后台处理。指纹绑定路径、大小、修改时间及版本，只有完整且校验通过的副本才原子发布。`/playback/<媒体ID>/<指纹>` 每次读取重新验证原件权限与版本，并沿用有界 Range；正在使用的副本有租约，淘汰不影响当前播放。缓存总预算 2 GiB、单副本 1 GiB，准备最多 2 小时；转换过程中单副本检测允许一个轮询间隔的小幅超额。格式扩展意味着更多容器能进入探测和兼容处理，不代表所有编码、损坏文件或超预算长视频已验收。

- `tests/unit/performance.unit.ts` 的 JS 索引、`tests/browser/performance.spec.ts` 的浏览器数据窗口测试，与 Rust `catalog::tests` 的数据库测试分别记录，不能互相代替。
- `tests/unit/media-layout.unit.ts` 对照全量扫描核验三种布局的视口结果，包括极端比例、边界和十万项样本。`tests/native/native-release-performance.mjs` 对已安装 Release 的各路由执行 20 次只读查询，记录 IPC P50/P95、返回大小、程序哈希和图库不变性；以 `AURE_CDP_URL` 指定调试端口、`AURE_PERF_PHASE` 区分测量阶段。热查询结果不能代替进程冷启动或原图呈现验收。
- `tests/native/native-desktop.mjs` 通过 CDP 验证真正的 Windows WebView2，只允许 `local.jingji.performance-audit` 独立应用标识。合成压力数据不等于十万张真实文件。报告由验证程序生成到 `verification/native-desktop/`。
- `tests/native/native-restart.mjs` 检查已持久化大库的进程重启、查询和前端堆；`tests/native/native-media.mjs` 检查独立真实大图／视频样本、缩略图失败重试及原件哈希。真实文件测试需预先准备可丢弃样本和精确权限，不等同于自动验收原生目录选择器。Release 验证通过 `JINGJI_NATIVE_BUILD=release` 记录构建模式。
- 首屏可交互 3 秒和常规搜索 P95 200ms 是参考验收预算；首次迁移、批量灌入、原图解码单独计时。压缩文件大小与解码像素内存分开记录。
- 应测冷／热缓存、磁盘速度、损坏文件、原文件改变、视频播放及 seek、连续浏览后的内存趋势。只有实际通过的样本可报告兼容；尚未承诺全部视频编码或图片格式。
- 元数据在查看器信息面板按需读取，图片包含尺寸和常见 EXIF，视频包含尺寸、时长和编码；按文件版本缓存，同时最多读取两项，不在列表排版时批量读取原图。AVIF 缩略图通过本机 FFmpeg 生成。
- 文件维护通过 `catalog/maintenance.rs` 和 `infrastructure/catalog-maintenance.ts` 集中适配：重扫保留缺失引用；目录重新定位及单文件重新关联保留稳定媒体 ID；备份恢复校验版本、表结构和引用后事务替换。手动提交前备份当前图库，原始媒体只读。目录同步为默认关闭的前台轮询，每 30 秒至多检查 32 个登记目录，不等同于系统级实时监听。
- 更大规模扫描、完整格式元数据、系统级实时监听，以及全图库真实媒体的长时间稳定性仍需独立任务与真实样本验收。
- 后续优先缩小深度浏览后的刷新范围：当前刷新会重新读取所有已加载窗口，基础上下文仍包含全部模特；大量窗口或模特时重复工作随规模增长。优化前记录刷新请求数、IPC 字节和呈现 P95，并核对排序、删除、关联变化及视口位置，不能直接丢弃屏外元数据导致返回失败。
- 多实例同时编辑仍缺实体/关系 revision 冲突检测；完整草稿保存可能覆盖另一实例的新关系。后续应返回明确冲突并保留草稿，或提交关系增删命令；不要把事务与聚焦刷新当作已解决冲突。同实例排队修改读取执行时最新快照，失败后仍允许后续修改。

选型依据：[SQLite 桌面应用存储](https://www.sqlite.org/whentouse.html)、[rusqlite 与许可](https://github.com/rusqlite/rusqlite)、[image 解码限制](https://docs.rs/image/latest/image/struct.Limits.html)。
