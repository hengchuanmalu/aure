# 产品与页面规范
基线 2.0 · 2026-09-27。布局以个人母系统应用后的前端为准，旧图册保留作历史参考。

## 产品目标
本地写真收藏、浏览与整理。图片和视频是核心内容；以 Hero、横向轨道和封面组织内容，不采用后台看板结构。桌面使用 SQLite 与真实文件引用，浏览器 mock 服务于演示和回归；不扩展账号、云同步、推荐服务、识别模型或发布系统。

### 产品哲学与取舍

以下归纳来自已明确的项目要求；具体界面偏好仍以当前指令及个人母系统的确认范围为准。

- **收藏属于使用者**：离线保存元数据，引用原件；移出关系、备份元数据与删除原件分别表达，不替使用者改名、移动或转码原件。
- **图片是主角**：封面组织内容，沉浸浏览围绕单个媒体；工具按需出现，动效用于解释操作，不持续争夺注意力。
- **整理减少负担**：复用现有入口，确定性规则在后台执行；歧义留空、手动修改保留、失败可重试，不伪装智能匹配或成功。
- **内容连续可达**：连续滚动与按需查询配合，照片在前、视频在后；选择、返回、键盘操作和减少动态效果均保留。
- **响应与画质按用途分配资源**：列表用派生图，查看器看原件；浏览优先于后台吞吐，数据、节点、解码像素与磁盘缓存分别设预算。
- **长期维护依靠清晰契约**：界面可替换，完整编辑草稿与页面窗口区分；业务、平台差异与失败状态明确，源码和本次验证优先于历史结论。

性能优先、体积适度是当前工程取舍：在原件安全与结果正确的前提下，优先减少重复读取、解析与解码，再控制发布体积。不得为了缩小 exe 改用明显更慢的优化档，也不为了少量方便把完整运行时和所有媒体工具强制塞入基础包。可选依赖须说明能力边界和缺失反馈；跨电脑可运行性按 [环境矩阵](05-acceptance.md#运行环境与发行验收) 实测。

## 页面结构与路由建议
路由仅为实现默认，可由 React 客户端路由承担，非外部 API。

| 页面 | 建议路径 | 布局与行为 |
|---|---|---|
| 发现 | / | 头像筛选、主次焦点网格、图集展台、最近更新、最近浏览、我的收藏、标签及模特浏览 |
| 写真库 | /library | 封面网格、搜索、模特横向选择、排序 |
| 写真详情 | /albums/:id | Hero 与描述，关联模特/Tag，全部/照片/视频筛选，混合媒体网格 |
| 创建写真 | /albums/new | 手动编辑名称、编号、封面、标签和关联模特；现有文件夹入口后台自动导入，无单独匹配页 |
| 编辑写真 | /albums/:id/edit | 同创建表单，独立草稿，保存后更新所有引用 |
| 媒体浏览 | /albums/:id/view/:mediaId | 单个图片或视频，默认隐藏应用工具栏 |
| 模特 | /models | 多人圆形小头像网格，姓名/地区/写真数量；搜索及风格筛选 |
| 模特详情 | /models/:id | 左资料右背景，下方显示关联写真集 |
| 模特编辑 | 详情上的弹窗 | 仅由“编辑资料”进入；统一草稿与保存 |
| 标签 | /tags | 顶部标签与模特横向筛选、独立多选、已选条件与匹配写真；/tags/manage 保留创建、修改及分组管理，旧 /settings/tags 跳转至此 |
| 收藏 | /favorites | 写真集 / 媒体分栏，媒体含图片和视频 |
| 最近浏览 | /recent | 按最近时间去重，继续到上次媒体；可清空记录 |
| 设置 | /settings | 动效偏好、演示数据重置；后续存储/缓存状态明示未接入 |

一级 Sidebar：发现、写真库、模特、标签、收藏、最近浏览、设置；设置默认置底。长按拖动或 Alt + 上下方向键调整顺序，顺序保存在本地设置。标签页使用窄主导航与完整内容区，标题「标签」下不显示说明小字，右上主操作为「添加标签」。顶部横向排列标签与圆形模特筛选，点击标签独立切换选中，不清除其他已选项；多个标签同时满足。下方显示匹配数量与可独立移除的已选条件，提供清除全部。写真库与标签页不提供右上角筛选按钮及展开面板；标签和模特条件通过横向栏选择。标签匹配与全库计数包含写真本身或其媒体上的标签。各项目悬停和选中背景独立淡入淡出，不跨项目移动，无原生 title 提示。详情返回保留来源页筛选和滚动位置。沉浸浏览不显示 Sidebar。

## 首页与写真
- 写真详情上方按 2026-10-08 用户参考图采用横版封面横幅：图片铺满圆角容器，底部渐暗承载白色信息；左下依次显示真实照片/视频数量、标题、圆形模特头像与姓名、编号、文件夹声明值和更新日期。收藏位于右上，白色「浏览写真」按钮位于右下；红色移出图标位于封面上方、返回按钮所在行的右端，移出保留确认提示。编辑沿用页面顶部入口；2026-10-11 用户明确要求向下滚动时浏览按钮吸附到编辑按钮的同一位置并覆盖它，向上回到封面时归位、重新露出编辑按钮。两按钮使用相同尺寸与横向位置，仅在浏览按钮接近编辑按钮下边缘 8px 内时吸附，回程超过 24px 时释放；触发后以同一个进度值同步按钮贴合与封面退出，将写真筛选栏置于顶部栏下方。后续滚动或操作可打断，普通内容滚动沿用原生行为；减少动态效果时直接完成，键盘滚动直接定位按钮。吸附沿用同一个按钮节点。副标题、简介和标签继续保存在资料编辑器，本横幅不展开。下方保留筛选与媒体网格；不显示「重新扫描」「重新定位文件夹」按钮（2026-10-11 用户要求）。布局显式标记为 landscape，媒体、资料与操作区域独立；竖版封面方案暂不实现，后续另设布局分支，不根据原图比例自动套用。首页精选封面和图集展台进入对应写真集。
- 模特轨道使用圆形头像；写真轨道使用统一 3:2 封面。
- 首页头像筛选作用于焦点网格和图集展台；全库轨道保持各自的明确范围。全局搜索进入写真库，模特页搜索仅查询模特。
- 焦点网格和图集展台使用当前数据的稳定顺序，不声称 AI 个性化或智能推荐。
- 写真封面、日期、数量、收藏等来自数据，创建/最近更新时间区分。
- 详情网格混合图片和视频；媒体总数与照片/视频数分别计算。无视频时只显示照片数。
- 标签同类多选默认 AND；模特多个选项默认 OR；不同维度 AND。筛选器可清空，空结果有复位入口。
- 所有界面不提供批量标签入口和对应的卡片选择模式。写真卡片直接打开详情，写真详情点击媒体直接进入浏览。
- 删除写真/媒体的界面语义默认为移出收藏库或解除关联，不删除磁盘原件。

## 模特
- 列表每项为圆形头像 + 名称 + 地区/关联写真数量 + 简短风格，不把它做成单人的照片墙。
- 列表“新建模特”用于创建；已有模特的修改统一进入详情的“编辑资料”，不另设列表快捷修改菜单。
- 人物详情按 2026-10-08 用户确认的效果图及补充：左栏圆形头像与姓名/别名横向并列，所有简介、详细字段与社交链接统一在头像行下方、同一左栏内排列；完整封面独立在右栏。详细字段采用自然文字行，不使用独立「详细资料」标题、表格式标签列或顶部折叠栏。背景与头像支持查看大图，无背景时不预留空图框。
- 人物详情不出现“浏览写真集”“更换背景”“添加自定义资料”或常驻输入框。头像与背景在统一「编辑资料」中设置并保存。
- 详细字段可增删、排序、修改标签与值；身高/生日/体重/发色等是示例，不是强制收集项。姓名必填，其余可空。
- 统一文字区默认预览约三行，长内容底部渐隐；「展开更多 / 收起」放在左栏文字区末尾靠右的位置（用户指向效果图 x=34.6%、y=86%），不放到整页或封面右下角。展开后末行保留柔和渐隐，短内容不显示无效开关。收起时文字区内链接不参与键盘交互；展开后键盘聚焦链接时取消渐隐，保留可读性。展开区按实际内容增高，关联写真集位于两栏下方；此前的标题行折叠方式由本次确认取代。
- 下方显示关联写真集。用户可通过写真封面进入详情。
- 模特的姓名或资料不从照片外貌推断；示例人物使用虚构信息，数据绑定保证同一人物的一致性。

## 标签与派生页面
- Tag 分组示例：风格、场景、季节、情绪、服装。用户可自定义。
- 支持标签创建、修改、分组，以及在资料编辑中关联标签。
- 删除标签解除引用；删除分组将标签移到未分组，保留标签。
- 收藏页沿用 AlbumCard/MediaCard；最近浏览沿用同组件加时间与继续浏览入口，不新增仪表盘。
- 设置用简洁分区表单。首轮真实可用项为动效偏好和重置 mock；未接入功能不显示虚假成功提示。
- 写真创建编辑采用左右分栏：左侧“封面”和底部封面缩略图选择，右侧写真信息及关联模特；仅关联模特列表纵向滚动，表单、封面和上下操作栏保持固定。沿用统一保存语义；不显示副标题、简介或写真内容选择区，保留旧资料字段；不要挪用人物自定义字段规则作为写真必填字段。
