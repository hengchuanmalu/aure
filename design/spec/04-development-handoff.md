## 类型与数据边界
| 类型 | 最小职责 |
|---|---|
| Album | id、名称、副标题、简介、封面媒体引用、创建/更新时间、收藏；有序媒体关联 |
| MediaItem | id、kind: image/video、本地路径或演示资源引用、尺寸、大小、可选拍摄时间、标签、收藏/喜欢/评分 |
| ImageMetadata | 可选相机/镜头/焦距/光圈/ISO 等 EXIF；未知使用空值 |
| VideoMetadata | 时长、poster 引用、可得容器/编码信息；解码失败状态不写成“已支持” |
| ModelProfile | id、名称、别名、简介、独立头像/背景及焦点、档案照片、社交链接、可排序自定义字段 |
| CustomField | 稳定 id、分组、标签、文本值、顺序；不要把全部人物属性硬编码为必填列 |
| Tag / TagGroup | id、名称、分组关系；写真及媒体多对多 |
| AlbumModel / AlbumMedia | 写真与模特多对多、写真与有序媒体关系 |
| RecentView | albumId、mediaId、最后浏览时间；正式浏览记录与悬停预览分离 |
| Settings | 动效偏好与演示数据版本；音量可保留为会话设置 |

- 首轮用异步 Repository 暴露查询、保存、关联、收藏、评分、最近浏览；React 组件不得散落直读 localStorage。
- MockRepository 用带版本的 localStorage 保存元数据修改；媒体二进制通过本地打包资源 URL 加载，不把图片或视频 base64 存入 localStorage。
- 创建/编辑人物共享草稿；保存时一次更新整个资料及关联，避免切分区产生部分提交。
- 封面选择遵循图片或视频 poster 引用，不在数据库存储原图；原件留在用户目录，缓存独立。
- 预留 MediaSourceResolver、FileScanner、ThumbnailService、MetadataService、SearchRepository；真实路径与渲染 URL 分离。
- 后续 SQLite 持久化元数据、关系、索引及 schema 版本。此轮不生成空迁移来冒充已接入数据库。
- 本地文件授权与媒体协议作用域在接入阶段明确收敛到用户选择的目录，UI 不直接获得任意路径读写能力。

## 依赖复用
2026-09-28 实施更新：按个人母系统 UIP-001 采用 shadcn/ui（Radix）+ Lucide，统一 CSS Tokens；状态过渡沿用 Motion，Windows 行为沿用平台适配。组件来源及本地定制见 `02-design-system.md`，版本以锁文件为准。
不要直接套用营销页的 taste-skill 默认效果；仅采用动效性能、状态反馈和减少动态效果原则。

## 视频兼容与失败边界
- 先验证 WebView2 内的实际媒体播放，包括本地文件、音轨、seek、拖动、全屏与缩略图。
- 首轮验收至少准备一个经实测可播放的 MP4/H.264 + AAC 演示文件；这是目标样本，不是对所有 MP4 的兼容承诺。
- 记录实际可播放的容器/编码组合。MOV/MKV/HEVC 等不能仅凭扩展名判定支持；不静默转码或改原件。
- 若用户真实图库包含 WebView2 无法解码的格式，需要再评估播放器/转码方案、分发体积与许可证；当前没有该兼容性决策。
- 无法播放应保留返回/换项、给出原因提示；不把全部失败都标作文件损坏。

- AI 人物资料只作为明确标识的虚构演示；mock 关联保证每个相册内身份与说明一致。
- 字体使用本机系统栈；图标来自单一可用图标库，不从截图截取文字或图标。
- 本设计交付不包含网站发布、安装器签名、自动更新服务或云端接口。
